# Первичная онтология из odmkey (пайплайн для интеграции с ONTOL)

`build_primary_ontology.py` в два шага:

1. Известные пары `pairs_w_relation.json` (дискретка) — проверенный текстовый поиск
   (тот же, что в `build_chunks_dataset.py`: словоформы понятий в тексте, а не позиция
   `\odmkey`, который ставится один раз на понятие). Даёт покрытие **391/402** пар.
2. Новые пары вне дискретки — из совместной встречаемости `\odmkey` (сущность
   `definition`) в окне 2 соседних `semantic_block`. Полный текстовый перебор всех
   ~1465 понятий (~1млн пар) тут не потянуть, поэтому только для новых пар.

Тип связи — шаблоны из задачи 3.2. При конфликте с дискреткой побеждает дискретка.

- `data/ontology_errors.jsonl` — датасет ошибок: `mismatch` (не совпало с дискреткой),
  `novel` (нашёл, чего нет в дискретке), `missed` (есть в дискретке, не нашёл).
- `data/ontology_final.json` — итоговая онтология (дискретка + новые пары от DiGr).

## Результат прогона на всём корпусе

Покрытие дискретки: **391/402** (~97%). Из них верно **152/350** (43.4%, совпадает
по порядку величины с точностью из задачи 3.2 — тот же классификатор). `novel`: 1665
пар вне дискретки — тип связи для них шаблонами не проверен ни с чем, качество неизвестно.

## Известное ограничение

Для новых (`novel`) пар индекс `\odmkey` — не то же самое, что имя в
`pairs_w_relation.json` (там короче и без англ. глосс: `"Область (domain)!интерпретации
(of interpretation)"` vs `"Область интерпретации"`). После очистки (`clean_index`) точное
совпадение — 118/307 уникальных имён дискретки. Остальное требует нечёткого
сопоставления, для этого в проекте уже есть `resolve_ontology.py` (помечен как legacy) —
не переделывал его сейчас. На покрытие дискретки (шаг 1) это не влияет, там сравнение
идёт по тексту, а не по odmkey.

## Запуск

```bash
python -m venv .venv
.venv/Scripts/pip install -r requirements.txt
PYTHONPATH=src PYTHONIOENCODING=utf-8 .venv/Scripts/python build_primary_ontology.py
PYTHONPATH=src .venv/Scripts/python -m pytest -q tests/
```
